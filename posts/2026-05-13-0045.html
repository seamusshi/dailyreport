OpenClaw 官方动态

🚀 OpenClaw 2026.5.2 正式版发布 —— 性能回归修复与插件架构升级

5 月 3 日，OpenClaw 发布 2026.5.2 稳定版，核心解决了 4 月底 2026.4.29 版本引入的 CPU 占用过高、WebUI 卡顿等性能回归问题。主要升级包括：外部插件安装流程全面重构（npm-first 迁移、过期配置修复、缺失包载荷处理、Beta 通道回退机制）；Gateway/Agent 热路径精简优化；新增 /think default 和 /fast default 命令以清除会话覆盖并继承配置默认值。

5 月 9 日紧接着发布 2026.5.9-beta.1，进一步引入：统一模型目录注册（支持文本、图像、视频、音乐多模态提供商）、Codex 模型支持升级至 0.130.0、oc-path 插件（ surgical oc:// 文件访问）、ACP agent 进程 args 数组支持空格路径、Tini 容器信号转发等底层可靠性改进。

来源：OpenClaw GitHub Releases / openclaw.com.au/updates

🔧 2026.4.20 / 4.25 系列版本 —— 生产级可靠性打磨

4 月下旬的连续版本更新没有追逐 flashy 功能，而是聚焦运维人员实际感受到的痛点的修复：cron 运行时执行状态拆分到独立的 jobs-state.json 文件，使 jobs.json 保持干净以便 git 追踪；内置会话修剪提前执行，防止膨胀的 cron 和执行历史威胁 Gateway 启动；token 用量报告增强，更好地支持缓存目录和配置模型的定价计算。

2026.4.25 版本则完成了 Voice/Telemetry/Browser Automation 的全面生产就绪化升级，新增 Azure Speech、小米、ElevenLabs v3、火山引擎等 6 大 TTS 提供商支持，以及聊天级自动 TTS 控制、Personas 角色系统和 per-agent 覆盖配置。

来源：openclaw.com.au/updates / OpenClaw changelog

🌐 浏览器控制架构转向 —— 从 Chrome 扩展到 Existing-Session

OpenClaw 正在从 legacy Chrome 扩展 relay 路径迁移到 existing-session / user 浏览器附着模式，包括通过 userDataDir 支持 Chromium 家族配置文件。这意味着 Agent 可以直接附着到已登录的真实浏览器会话，保留真实登录态和审批流程，无需脆弱的扩展中间层。

此外，未发布路线图中的 pluggable sandbox backends、Firecrawl 搜索与抓取工具、/btw 侧问流程、GitHub main 直接安装/更新支持，均显示 OpenClaw 正在从"玩具 Agent Shell"进化为真正的生产基础设施。

来源：OpenClaw GitHub PR #48170 / PR #47630 / changelog

⚠️ 社区反馈：文档与版本一致性仍是最大痛点

社区在 GitHub 上持续反馈一个核心问题：文档与代码版本之间的"真相漂移（truth drift）"。例如 CLI backends 快速入门文档推荐 openclaw agent --model ... 标志，但该标志在 2026.4.15 版本中并不存在；另有报告指旧版本 April builds 在 PTY/exec 事件延迟到达时 Gateway 不稳定。OpenClaw 2026.4.20 的修复方向与此高度一致。

📌 核心功能更新详情

Cron 状态分离与 Gateway 稳定性

2026.4.20 将 cron 执行状态从 jobs.json 拆出到 jobs-state.json，实现任务定义与执行状态的解耦。这使版本控制中的 jobs 文件保持干净，同时允许运维人员独立监控运行时状态。配合更早触发的会话修剪和 token 用量报告的缓存目录支持，解决了大规模部署中 Gateway 启动延迟和状态膨胀问题。

模型目录注册统一化（2026.5.9-beta.1）

新增 providerCatalogEntry 清单、共享媒体列表帮助、实时目录缓存和 per-model 视频能力叠加层，统一支持文本、图像、视频、音乐四类提供商。这意味着 OpenClaw 不再将模型视为简单的 API 端点，而是建立完整的提供商能力注册表，使 Agent 在多模态任务中自动选择正确的模型和格式。

安全加固：Fail-Closed 默认与审计边界

近期版本在安全层面的累计改进包括：Slack 交互事件更严格地遵循所有者白名单、附件路径解析失败时关闭（fail-closed）、危险的安全审计标志无法通过模型面向的 Gateway 配置工具新启用、浏览器 SSRF 行为规范化、Control UI 替换 ReDoS 风险的 Markdown 解析器。整体趋势：更少的隐藏转换，更好的运行时清晰度，更强的边界纪律。

NVIDIA NemoClaw —— 企业级安全部署方案

NVIDIA 推出基于 OpenClaw 核心的 NemoClaw 企业版，主打安全可控的 AI Agent 部署。方案与 OpenClaw 共享核心运行时，但在隔离、审计、访问控制和企业 SSO 方面做了深度增强。这是对 OpenClaw 社区版安全短板的直接回应，填补了从个人实验到企业生产之间的关键空白。

文生图模型精细化路由 —— 不同 Agent 用不同画质

高级技巧：为不同智能体配置隔离的 .env 文件，实现"全局技能统一部署 + 局部环境变量隔离"。

  1. 在写作 Agent 的 workspace .env 中配置 QWEN_IMAGE_MODEL="qwen-image-2.0-pro"
  2. 在日常对话 Agent 的 workspace .env 中配置 QWEN_IMAGE_MODEL="qwen-image-2.0"
  3. Skill 代码中使用 process.env.QWEN_IMAGE_MODEL 读取，自动按 Agent 隔离

效果：高质量输出场景用 Pro 版模型，日常场景用标准版，精准控制成本。
