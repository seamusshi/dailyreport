📌 核心功能更新详情

浏览器控制：从「扩展 hack」到「真实会话附加」

OpenClaw 的浏览器控制策略正在经历范式转移：

  • 旧路径（逐渐废弃）：Chrome 扩展中继，依赖 HMAC-SHA256 派生令牌，配置复杂，易受扩展更新影响
  • 新路径（推荐）：existing-session / user 附加，支持 profile="user" 和 profile="chrome-relay"，通过 userDataDir 指定 Chromium profile 路径
  • 好处：保留真实浏览器登录态、减少 setup 诅咒胶带、更接近严肃运维的实际工作方式、支持 batch act 和 selector targeting，自动化更顺滑

使用示例：browser: act {"kind":"navigate","url":"https://github.com","profile":"user"}

Active Memory：更 operator-controlled 的记忆系统

最新的 Active Memory 改进让记忆召回更可控：

  • per-conversation 过滤：通过 allowedChatIds 和 deniedChatIds 精确控制哪些对话可以触发记忆召回
  • bounded partial recall：部分召回摘要现在有界，不会因 sub-agent 超时而丢弃有价值的恢复上下文
  • timeout 注册修正：memory recall 现在正确注册为「配置超时 + 设置宽限期」，而非错误地占用最大预算

这意味着长时间运行的 Agent 在重启或恢复时，记忆系统更可靠，不会因为边缘 case 而「失忆」。

状态面板：从「装饰」进化为「运维遥测」

status/deep checks 现在真正服务于运维场景：

  • Discord transport degradation 和 gateway event-loop starvation 现在会在状态检查中暴露
  • async session-list hydration 有界，防止 Control UI 轮询时扫描 huge transcripts
  • manual cron run IDs 在任务完成后保留，支持事后关联追踪

OpenClaw 正在从「agent app」蜕变为「operator-grade infrastructure」。
